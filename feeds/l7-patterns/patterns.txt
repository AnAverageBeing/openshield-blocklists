# openshield-blocklists :: l7-patterns :: L7 attack-pattern signatures
# category: l7-patterns | one signature per line | spec: docs/FEED-FORMATS.md
# entries: 10
#
# HAND-CURATED feed — not built from remote sources. Each line is an L7
# drop signature for the OpenShield-XDP l7_sig_map:
#
#   name|proto|port|port_is_src|offset|min_payload|max_payload|pattern_hex|mask_hex
#
# Only highest-accuracy REFLECTION/AMPLIFICATION classes are admitted, and
# only as RESPONSE-side signatures (port_is_src=1): a match means "a packet
# arrived FROM a well-known amplifier service port carrying that service's
# response marker" — which, at a protected edge (game servers, enterprise
# apps, dedicated multi-tenant hosts, CDNs, bulk up/downloads), is only
# ever reflected attack traffic. A wrong pattern here false-positives on
# legitimate servers, so every entry documents its byte-level rationale;
# candidate signatures without a confident fixed marker are EXCLUDED and
# listed at the bottom with the reason.
#
# The engine compares (payload[offset+i] & mask[i]) == pattern[i]; an empty
# mask means exact match (all-ff). offset is payload-relative (after the
# UDP/TCP header). min_payload/max_payload bound the L4 payload length;
# max_payload 0 = no cap.

# ── DNS amplification ────────────────────────────────────────────────────
# UDP from source port 53, DNS flags high byte (offset 2) with the QR bit
# set (0x80 = "this is a response"), payload >= 512 bytes. Legit resolvers
# answer the host's own queries with small A/AAAA responses; >=512-byte
# responses are the classic ANY/DNSSEC amplification product. Caveat: very
# large legitimate DNSSEC answers also match — min_payload=512 is the only
# guard, so hosts doing heavy DNSSEC resolution should not enable this.
# Confidence: byte pattern certain (RFC 1035 header layout).
dns-amplification|udp|53|1|2|512|0|80|80

# ── NTP monlist (mode 7) amplification ───────────────────────────────────
# UDP from source port 123, first byte = response flag (0x80) + mode 7
# (0x07), any version / more-fragments bit: pattern 0x87 mask 0x87.
# Mode 7 is the deprecated ntpdc private protocol whose monlist request is
# the ~550x amplifier; no modern ntpd answers mode 7 at all, so a mode-7
# RESPONSE is never legitimate traffic to a protected host.
# Confidence: certain (rm_vn_mode layout from ntp_request.h; the same
# filter ISPs have deployed for CVE-2013-5211 since 2014).
ntp-monlist|udp|123|1|0|100|0|87|87

# ── SSDP / UPnP reflection ───────────────────────────────────────────────
# UDP from source port 1900 whose payload starts with the literal
# "HTTP/1.1" (48 54 54 50 2f 31 2e 31) — the first line of every SSDP
# M-SEARCH response ("HTTP/1.1 200 OK"). Servers do not send M-SEARCH
# discovery, so an SSDP response arriving at a protected edge is reflected
# attack traffic by construction. min_payload=100 skips truncated junk.
# Confidence: certain (UPnP Device Architecture, SSDP response format).
ssdp-reflection|udp|1900|1|0|100|0|485454502f312e31|ffffffffffffffff

# ── CLDAP reflection ─────────────────────────────────────────────────────
# UDP from source port 389, payload byte 0 = 0x30 (BER SEQUENCE tag — every
# LDAP/CLDAP message starts with it), payload >= 512 bytes. CLDAP is the
# connectionless-LDAP reflection vector (CVE-2016-7434 class); its only
# legitimate use is AD domain-controller locator, whose responses are small
# (a few hundred bytes), so the 512-byte floor keeps those alive while
# matching the multi-KB amplified searchResEntry floods.
# Confidence: byte certain (RFC 4511 BER encoding); size threshold is the
# conservative guard — AD-joined hosts doing CLDAP discovery of very large
# DCs should not enable this.
cldap-reflection|udp|389|1|0|512|0|30|ff

# ── memcached UDP amplification ──────────────────────────────────────────
# UDP from source port 11211, bytes 6-7 of the 8-byte memcached UDP header
# = 0x0000 (the reserved field, always zero on the wire), near-MTU payload
# (>= 1400 bytes). memcached UDP is the record-holder amplifier (~50000x);
# the UDP protocol has been disabled by default since memcached 1.5.6, so
# the only hosts still emitting large UDP datagrams from 11211 are the
# abused ones. A host that is itself a memcached-over-UDP CLIENT pulling
# multi-KB values would match — documented, accepted: UDP memcached is
# deprecated and vanishingly rare.
# Confidence: certain (memcached binary-over-UDP header: request id,
# sequence, total datagrams, reserved=0).
memcached-udp|udp|11211|1|6|1400|0|0000|ffff

# ── WS-Discovery (WSD) reflection ────────────────────────────────────────
# UDP from source port 3702 whose payload starts with the literal "<?xml"
# (3c 3f 78 6d 6c) — the XML declaration opening every WS-Discovery
# response (Hello / ProbeMatches / ResolveMatches SOAP envelopes,
# SOAP-over-UDP per WS-Discovery 1.1). WSD is the 2019-era record
# amplification vector (~500x+ observed) abused via exposed ONVIF/printer/
# embedded devices; protected servers never run WS-Discovery discovery
# clients, so a WSD response arriving at the edge is reflected attack
# traffic by construction. min_payload=500 matches the bloated ProbeMatches
# bodies (typically 700B-2KB) and skips any truncated junk. Responders that
# omit the XML declaration are missed by design (a miss is safe).
# Confidence: byte certain for the response shape (SOAP/XML over UDP);
# the marker anchors at payload offset 0.
ws-discovery|udp|3702|1|0|500|0|3c3f786d6c|ffffffffff

# ── STUN binding-success reflection ──────────────────────────────────────
# UDP from source port 3478, RFC 5389 message header: message type 0x0101
# (Binding Success Response) at offset 0 AND the magic cookie 0x2112A442 at
# offset 4; the 2 length bytes in between are masked out (pattern/mask
# 0101 0000 2112a442 / ffff 0000 ffffffff). The cookie separates STUN from
# any other protocol that happens to open with 01 01 on the same port.
# min_payload=100 is above a bare binding answer (~32-68B) so the host's
# own STUN client (WebRTC/SIP/ICE — uncommon on server edges, but possible)
# keeps small legit responses alive; amplification floods pad responses
# well past that. Legacy RFC 3489-only responders (no cookie) are missed
# by design.
# Confidence: byte certain (RFC 5389 §6 fixed 20-byte header layout).
stun|udp|3478|1|0|100|0|010100002112a442|ffff0000ffffffff

# ── CoAP 2.xx response reflection ────────────────────────────────────────
# UDP from source port 5683, RFC 7252 header byte 0 = version 1 (01 in the
# top two bits), byte 1 = response code class 2 (010 in the top three bits,
# i.e. any 2.xx success code: 2.01 Created … 2.05 Content): pattern 40 40
# mask c0 e0. Message type (CON/NON/ACK/RST) is deliberately NOT restricted:
# reflected CoAP floods arrive as piggybacked ACK or separate NON/CON 2.05
# Content responses to spoofed requests (/.well-known/core discovery is the
# classic ~30x+ vector), and observe notifications share the same bytes.
# Residual FP: a protected host that is itself a CoAP client (IoT gateway
# style) receives legit 2.xx responses — rare on server edges; min_payload
# 100 keeps the smallest answers alive.
# Confidence: byte certain (RFC 7252 §3 header layout); class-wide match
# accepted per the response-side admission policy (same reasoning as SSDP).
coap|udp|5683|1|0|100|0|4040|c0e0

# ── mDNS response reflection ─────────────────────────────────────────────
# UDP from source port 5353, DNS header flags high byte (offset 2) with the
# QR bit set (0x80), payload >= 200 bytes — same header logic as the DNS
# entry (RFC 1035/6762 share the wire header) on the mDNS port. mDNS
# reflectors answer spoofed ANY queries with large PTR/SRV/TXT responses.
# Residual FP risk (accepted, documented): mDNS is link-local by design
# (224.0.0.251, TTL 255) and unusual on server VLANs — but a host that
# legitimately runs an mDNS responder querier (avahi, printer/IoT
# discovery on the LAN) sees real responses from sport 5353; the 200-byte
# floor is the only guard for those. Do not enable on such hosts.
# Confidence: byte certain (RFC 1035 header layout, RFC 6762 reuse).
mdns|udp|5353|1|2|200|0|80|80

# ── NTP mode 6 (ntpq control) reflection ─────────────────────────────────
# UDP from source port 123, first byte = response flag (0x80) + mode 6
# (0x06), any version / error bit: pattern 0x86 mask 0x87 — the same
# RM_VN_MODE byte layout family as the mode-7 entry above, for the ntpq
# control protocol. Mode 6 query responses (mrulist in ntpd 4.2.8p+, large
# statistics dumps) are the post-monlist NTP amplifier class. Residual FP:
# a host that actively polls remote NTP servers with ntpq control queries
# receives legit mode-6 responses — rare on protected servers; min_payload
# 200 matches the multi-fragment mrulist/stat floods (fragments up to
# ~480B) and skips small single-variable answers.
# Confidence: byte certain (RM_VN_MODE layout, ntp_control.h; same header
# family as the mode-7 signature ISPs have deployed since 2014).
ntp-mode6|udp|123|1|0|200|0|86|87
